* homelab

This repository holds the smolvm host/guest automation. The automation is
organized as capability roles driven by thin profile plays; CONTEXT.md
documents the vocabulary.

* Layout

- ansible.cfg -- repository-wide Ansible defaults (inventory, role path, filter plugins)
- inventory/ -- the host inventory
- playbooks/ -- the profile plays, one directory per component
- filter_plugins/ -- repository-wide filter plugins
- docs/ -- per-component manuals and architecture notes
- roles/ -- capability roles (bind_mounts: smolvm host/guest share binds)
- CONTEXT.md -- the project vocabulary

* Running

Ansible runs on the smolvm host. Every play is started from the repository
root, so ansible.cfg discovery picks up the inventory, the role path, and the
filter plugins.

* Components

The bind_mounts capability role (roles/bind_mounts/) shares host
directories with smolvm guests. Its manual is docs/bind-mounts/README.org
and its architecture notes are docs/bind-mounts/architecture.org.

The smolvm machine profile play lives at playbooks/smolvm/ (machine
lifecycle, guest packages, and bind-mount convergence through the
bind_mounts role). Its configuration lives outside the repository, in the
invoking user's home: ~/.config/homelab/playbooks/smolvm/vars.yml.
